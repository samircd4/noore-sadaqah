# Languages (i18n)

Bengali (`bn`) is the default; English (`en`) is second and **part of v1** (DECISIONS.md D10).
Frontend: **next-intl**. Backend: Django `gettext` (admin, SMS, email, receipts) + `*_bn`/`*_en` content fields.

## Decisions

| Question | Decision |
|---|---|
| URL style | `/bn/...` for Bengali, `/en/...` for English; `/` and any unprefixed URL redirect to `/bn/...`. next-intl `localePrefix: "always"` (DECISIONS.md D16) |
| English at launch? | **Yes.** Every UI label and every page in English; content (`*_en` fields) as far as translated. Translator: open decision (DECISIONS.md open-1) |
| Missing English content | The API falls back to Bengali and the page keeps working; never show an empty title |
| Admin area | Django admin in Bengali; staff may switch to English in their browser (Django `LocaleMiddleware`) |
| Remembering the choice | The URL carries the language (`/bn/…` or `/en/…`), so links keep it. **No automatic redirect** by browser language or cookie (`localeDetection: false`): many phones in Bangladesh are set to English, but the site is Bengali first |
| `<html lang>` | `bn` or `en` from the locale |
| SMS, email, receipt language | `Donation.locale` / `User.preferred_locale`, set from the page language at the time of donating or logging in |

## Three kinds of text

1. **Frontend UI labels** (buttons, form labels, errors, nav): `frontend/messages/bn.json` and `en.json`.
2. **Content** (program text, fund story, news): Django `*_bn` / `*_en` fields. The **API resolves the language**
   from `Accept-Language` and returns plain `title`, `summary`, `body_html` …, so the frontend doesn't pick fields.
   Backend helper:
   ```python
   # core/utils.py
   def translated(obj, field, language):
       if language == "en" and getattr(obj, f"{field}_en", ""):
           return getattr(obj, f"{field}_en")
       return getattr(obj, f"{field}_bn")
   ```
   The Next.js `apiGet()` always sends `Accept-Language` with the current locale.
3. **Backend text** (SMS, email, receipt PDF): Django `gettext` / `{% translate %}` with
   `backend/locale/{bn,en}/LC_MESSAGES/django.po`, in the donation's language. SMS/email templates: NOTIFICATIONS.md.
4. **Django admin: English only** (`LANGUAGE_CODE = "en-us"`, no `LocaleMiddleware`). Content staff type in the
   `*_bn` fields is still Bengali; the admin's own labels, menus and messages are English.

## Message key naming (frontend)

- Grouped by area, `camelCase` keys, at most 3 levels: `nav.donate`, `donate.form.mobileLabel`, `errors.mobileInvalid`.
- Top-level groups: `common`, `nav`, `footer`, `home`, `donate`, `zakat`, `account`, `forms`, `errors`, `meta`.
- Never build sentences by joining keys; use ICU placeholders: `"raised": "{amount} সংগৃহীত"`.
- Both files must have the same keys. `npm run i18n:check` fails if any key is missing (runs in CI).

Example (`messages/bn.json`):

```json
{
  "nav": { "home": "হোম", "about": "পরিচিতি", "programs": "কার্যক্রম", "gallery": "গ্যালারি", "news": "সংবাদ", "contact": "যোগাযোগ", "donate": "দান করুন", "openMenu": "মেনু খুলুন" },
  "donate": {
    "form": { "fund": "তহবিল", "name": "নাম", "mobile": "মোবাইল", "amount": "পরিমাণ", "submit": "দান করুন", "or": "অথবা" },
    "oneTime": "একবার", "monthly": "মাসিক"
  },
  "errors": { "required": "এই ঘরটি পূরণ করুন", "mobileInvalid": "সঠিক মোবাইল নম্বর দিন (01XXXXXXXXX)", "minAmount": "সর্বনিম্ন {min}" }
}
```

> The design's quick-donate panel says "Or" in English; use `donate.form.or` → "অথবা".

## Error codes shared by both apps

- Zod schemas (`frontend/src/lib/validation/`) return **message keys** (`"errors.mobileInvalid"`), not text.
- DRF returns the **same keys without the prefix** (`"mobileInvalid"`, or `{"code": "minAmount", "min": 10}`); see API.md "Errors".
- `src/lib/api.js` maps a DRF error to `{ field: "errors.<code>" , params }`, and the form shows `t(key, params)`.
- One list of codes lives in API.md; adding a code means adding it to both `messages/*.json`.

## Numbers, money, dates

Frontend `src/lib/format.js`:

| Function | `bn` | `en` |
|---|---|---|
| `bnNumber(12500, locale)` | ১২,৫০০ | 12,500 |
| `bnDigits(2026, locale)` (years, IDs: no grouping) | ২০২৬ | 2026 |
| `taka(1000, locale)` | ৳১,০০০ | ৳1,000 |
| `bnDate(date, locale)` | ২০ অক্টোবর ২০২৬ | 20 October 2026 |
| `shortNumber(100000, locale)` | ১ লক্ষ+ | 100K+ |
| `toLatinDigits("১০০০")` | "1000" | |

- `Intl.NumberFormat("bn-BD")` / `"en-BD"`; dates always with `timeZone: "Asia/Dhaka"`.
- Inputs accept Bengali (০–৯) and English digits: `toLatinDigits()` runs before Zod. Django also normalises digits in the serializer.

Backend `core/templatetags/bn.py` (receipts, SMS, email) provides the same: `bn_number`, `taka`, `bn_date`, and
`amount_in_words_bn(1500)` → "এক হাজার পাঁচশত টাকা মাত্র" (Bengali counting: হাজার, লক্ষ, কোটি; unit-tested).
